## 3. CORE SCHEMAS & DATA STRUCTURES

### A. User Schema (`backend/models/User.js`)

* `Roll_Number`: Uppercase string, unique, indexed (e.g., `MCA25015` or custom format).
* `full_name`: String, required.
* `email`: Lowercase string, institutional format.
* `role`: Enum `['Student', 'Head', 'Faculty', 'Admin']`, default `'Student'`.
* `isVerified`: Boolean (true after OTP verification).
* `isFirstLogin`: Boolean (tracks if pre-provisioned faculty must update default credentials).
* `password_hash` & `password_salt`: Selected only via `+password_hash`.
* `organizationMemberships`: Array of objects enabling dynamic leadership:
```javascript
organizationMemberships: [
  {
    organization: { type: Schema.Types.ObjectId, ref: 'Organization' },
    title: { type: String, default: 'Member' }, // e.g. "CSR POC", "President", "Advisor"
    canModerate: { type: Boolean, default: false } // Determines application review rights
  }
]

```


* `joined_clubs`: `[{ type: Schema.Types.ObjectId, ref: 'Organization' }]`.
* `joined_committee`: `{ type: Schema.Types.ObjectId, ref: 'Organization', default: null }`.

### B. Temporary User Schema (`backend/models/TempUser.js`)

* Ephemeral model holding `{ Roll_Number, full_name, email, password_hash, password_salt, otp }`.
* `createdAt`: Date with TTL `expires: 600` (MongoDB automatically removes unverified attempts after 10 minutes).

### C. Application Pipeline Stages

* Pipeline states: `'Pending'` $\rightarrow$ `'Interview'` $\rightarrow$ `'Voting'` $\rightarrow$ `'Approved'` / `'Rejected'`.
* *Note:* "Tech Round" was permanently eliminated to fit general committee recruitment workflows.

## 5. RECENT IMPLEMENTATIONS & CRITICAL GOTCHAS

1. **Email Port 2525 Bypass:** Standard SMTP ports (465, 587) trigger an `ETIMEDOUT` on Render's free tier. Always configure Nodemailer with `host: 'smtp-relay.brevo.com'`, `port: 2525`, `secure: false`. The `from` header must match the verified Brevo registration email, not the internal SMTP username.
2. **Dynamic UI Nomenclature:** All user-facing references to "Organization" are replaced with **"Committee/Club"**. Internal API keys and schema field names remain `organization` / `organizationId` to prevent breaking backend mappings.
3. **Application Review Authorization (`applications.js`):**
* Students with `canModerate: true` in their `organizationMemberships` can fetch and review applications strictly for their assigned organization.
* The backend handles scoping: `query.organization = { $in: allowedOrgIds }`.


4. **Session Synchronization Issue (Pending Roadblock):**
* When promoting a user to POC via `/make-me-poc` or `/assign-leadership`, the database updates immediately, but the client-side JWT token and `localStorage` session hold stale claims until the user logs out and logs back in.
* Avoid applying duplicate array filters on `Dashboard.jsx` if the backend `/applications` route already returns an isolated dataset, as mismatched ObjectId string formats can empty the review table.

## 6. DEVELOPMENT RULES, DO'S & DON'TS

### DO'S

* **Preserve CommonJS:** Write backend code using `const express = require('express')` and `module.exports = router`.
* **Safe Population:** Always chain `.populate('student', 'full_name Roll_Number email role')` and `.populate('organization', 'name type')` on application queries so the frontend components receive readable names.
* **Case-Sensitivity on Linux:** Always match file imports identically to disk naming (e.g., `require('../models/Report')` vs `Report.js`) to prevent Linux deployment crashes on Render.
* **Token Integrity:** Whenever updating user roles or memberships, ensure the updated payload includes `organizationMemberships` with `canModerate` flags and `isFirstLogin`.

### DON'TS

* **Do Not Re-expose Operational Controls to Faculty:** Faculty coordinators must never see application decision buttons ("Accept", "Reject", "Move to Interview"). Their UI is strictly read-only.
* **Do Not Create Main User Records Before Verification:** Never run `new User().save()` on registration until the student has entered the valid 6-digit OTP code against `TempUser`.
* **Do Not Allow Public Role Selectors:** Never add an "Are you a Faculty/Head/Admin?" dropdown to the public registration form.
* **Do Not Hardcode Server URLs:** Always use `API_BASE_URL` imported from `config.js` to ensure seamless switching between `localhost:5000` and the production Render domain.
